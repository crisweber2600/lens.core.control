# Story E3-S2: Compose Candidate, Sufficiency, and Scope Drafts

Status: done

## Story

As an operator, I want raw context transformed into one bounded packet draft, so that the selected feature can be validated without premature topology.

## Implementation Context

- Dev implementation target: `NextLens` at `TargetProjects/nextlens/src/NextLens`.
- Implementation writes are allowed only under `TargetProjects/nextlens/src/NextLens`.
- Runtime draft/cache writes, if any, are allowed only under configured output roots and must not be accepted packet output until confirmation and receipt verification.
- Candidate extraction must preserve unranked deferred candidates as notes, not topology or roadmap truth.

## Acceptance Criteria

1. Given raw context contains possible feature slices, when candidate extraction runs, then it presents unranked candidates, requires exactly one selection, and stores deferred candidates only as unranked notes.
2. Given zero or multiple selected candidates remain, when the user tries to proceed, then the workflow blocks, explains the protective reason, and writes no packet.
3. Given the selected candidate lacks actor, problem, useful outcome, acceptance criteria, constraints, assumptions, included scope, or explicit out-of-scope, when sufficiency/scope stages run, then they collect or block with protective guidance and write no packet.
4. Given a draft is composed, when it is inspected, then it preserves raw user wording alongside normalized fields and keeps topology null/unpromoted.

## Tasks / Subtasks

- [ ] Extract possible candidate feature slices from raw context.
- [ ] Enforce exactly-one selected candidate before proceeding.
- [ ] Preserve deferred candidates as unranked notes only.
- [ ] Collect actor/user, problem, local outcome, acceptance criteria, constraints, assumptions, included scope, and explicit out-of-scope.
- [ ] Integrate validation/readiness outputs from E2-S2/E2-S3.

## Dependencies And Sequencing

- Depends on: E3-S1, E2-S2, E2-S3.
- This story should use existing validator and readiness outputs rather than reimplementing them in prompt prose.
- E3-S3 depends on this draft shape for preview and confirmation behavior.

## Dev Notes

- Candidate choices must not imply roadmap, dependency order, domain, service, capability grouping, adjacency, or promotion.
- Block missing included scope or explicit out-of-scope with the smallest corrective action and no write.
- Preserve raw wording and normalized fields for auditability.

## Test / Validation Expectations

- Prompt/eval fixtures for single feature, multi-candidate, missing out-of-scope, and valid-not-BMAD-ready drafts.
- Validator integration tests from E2-S2/E2-S3.
- No-write tests for all blocker paths.

- Do not write or require `feature.yaml`, governance publish, direct governance repo writes, governance docs mirror writes, Lens branch topology, Lens constitution runtime, release clones, `.github`, Lens control-repo implementation paths, current NextLens top-down runtime modules, Landscape, Derived Graph, Salmon, promotion, adjacency, pressure, roadmap, or service/domain/program truth paths.
