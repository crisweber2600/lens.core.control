# Story E3-S3: Render Preview, Dry Run, and Confirmation Token

Status: done

## Story

As an operator, I want a preview and deliberate confirmation before any write, so that I can revise, cancel, or confirm safely.

## Implementation Context

- Dev implementation target: `NextLens` at `TargetProjects/nextlens/src/NextLens`.
- Implementation writes are allowed only under `TargetProjects/nextlens/src/NextLens`.
- Runtime dry-run/preview writes nothing unless optional reports are explicitly requested under configured `reports_output_path`.
- This story selects the confirmation behavior: interactive writes require the exact token `CREATE PACKET`; headless writes require `--confirm`.

## Acceptance Criteria

1. Given a packet draft is valid enough to preview, when preview renders, then it shows selected feature, included scope, explicit out-of-scope, assumptions, acceptance criteria, constraints, provenance, intended write target, packet validity, BMAD readiness, and non-effects checklist.
2. Given the user chooses dry-run, revise, or cancel, when the flow returns to earlier stages or exits, then no packet, receipt, run metadata, governance file, release clone file, or top-down runtime file is written.
3. Given the user confirms interactively, when the final write is requested, then the token must be exactly `CREATE PACKET`.
4. Given headless mode is used, when `--confirm` is absent, then the create workflow blocks before write.

## Tasks / Subtasks

- [ ] Render preview with packet summary, validity, readiness, write target, and non-effects.
- [ ] Support revise, cancel, and dry-run paths with no packet write.
- [ ] Implement exact interactive confirmation token `CREATE PACKET`.
- [ ] Require explicit `--confirm` for headless writes.

## Dependencies And Sequencing

- Pressing Enter or any token other than `CREATE PACKET` must not write.
