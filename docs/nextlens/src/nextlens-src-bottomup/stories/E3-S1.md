# Story E3-S1: Implement Create Packet Skill Routing and Stage Prompts

Status: ready-for-dev

## Story

As an operator, I want a guided/headless create workflow with stable stage labels, so that the packet creator is understandable and testable.

## Implementation Context

- Dev implementation target: `NextLens` at `TargetProjects/nextlens/src/NextLens`.
- Implementation writes are allowed only under `TargetProjects/nextlens/src/NextLens`.
- Runtime create writes only under configured `packet_output_path` and `reports_output_path` after future validation and confirmation stories provide those gates.
- This story wires skill routing and stage prompts; it should not write accepted packets yet.

## Acceptance Criteria

1. Given a user asks to start from one feature, when `bul-create-packet` activates, then it routes through `context-intake`, `candidate-selection`, `local-sufficiency`, `scope-boundary`, `preview`, `confirmation`, `write`, and `receipt` stages.
2. Given context is displayed, when the stage begins, then it shows explicit/module context, output path, and runtime write scope before mutation and rejects branch, open-file, or cwd inference.
3. Given context resolution would rely on branch name, open editor file, or cwd, when the workflow starts, then it blocks and asks for explicit input or module config instead.
4. Given trigger evals inspect activation, when Lens lifecycle requests are used, then they do not activate this standalone module or require Lens governance/runtime constructs.

## Tasks / Subtasks

- [ ] Implement `bul-create-packet/SKILL.md` as a concise router to guided/headless prompt instructions.
- [ ] Define stable stage prompt files or resources.
- [ ] Display context, output path, and write scope before any mutation-capable stage.
- [ ] Add trigger tests or fixtures for positive Bottom-Up LENS prompts and negative Lens lifecycle prompts.

## Dependencies And Sequencing

- Depends on: E1-S1, E1-S2.
- This story sets up routing before E3-S2 composes drafts and before E3-S3/E3-S4 preview/write behavior.
- It must not bypass E2 validator, readiness, path guard, or verifier dependencies.

## Dev Notes

- Use "Start from one feature" as the primary entry phrase.
- Stage labels must be exactly: `context-intake`, `candidate-selection`, `local-sufficiency`, `scope-boundary`, `preview`, `confirmation`, `write`, `receipt`.
- Keep `SKILL.md` concise and move stage details to `prompts/` or `resources/`.

## Test / Validation Expectations

- Trigger evals for positive create prompts and negative Lens lifecycle prompts.
- Unit or prompt tests for stage labels and context display.
- No-write test for startup/context blockers.
