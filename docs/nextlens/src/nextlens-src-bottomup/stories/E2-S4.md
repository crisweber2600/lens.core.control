# Story E2-S4: Implement Path Guard and Forbidden-Write Fixtures

Status: done

## Story

As a safety reviewer, I want path plans denied before writes, so that packet creation cannot modify forbidden surfaces.

## Implementation Context

- Dev implementation target: `NextLens` at `TargetProjects/nextlens/src/NextLens`.
- Implementation writes are allowed only under `TargetProjects/nextlens/src/NextLens`.
- Runtime writes are allowed only under configured `packet_output_path` and `reports_output_path`.
- This story creates the reusable guard required before write-capable create workflow stories.

## Acceptance Criteria

1. Given a path under configured output roots, when the guard checks containment, then it passes and returns normalized path metadata.
2. Given a path outside configured roots or containing denied categories, when the guard checks it, then it fails with category, field, message, and recommendation.
3. Given a write-capable create story runs, when it plans writes, then it calls this guard before any file write.
4. Given forbidden-write fixtures target governance, release, landscape, graph, salmon, promotion, adjacency, pressure, `.git`, Lens lifecycle metadata, service/domain/program truth, or current top-down runtime paths, when tests run, then every fixture is blocked.

## Tasks / Subtasks

- [ ] Implement a path guard helper local to write-capable skills.
- [ ] Resolve paths with `Path(...).expanduser().resolve()` before containment checks.
- [ ] Add data-driven denied categories and structured failure output.
- [ ] Add forbidden-write fixtures for all denied categories.

## Dependencies And Sequencing

- Depends on: E1-S2, E2-S1.
- This story must precede E3-S3 and E3-S4 write planning and confirmation work.
- It pairs with E2-S5 to make receipt and non-effects verification credible before accepted create success.

## Dev Notes

- Do not use ad hoc string-only path validation where the guard should be called.
- Denied categories must include `.git`, governance, release, landscape, graph, salmon, promotion, adjacency, and pressure at minimum.
- Allowed runtime roots come from setup config keys, not branch, editor, or cwd inference.

## Test / Validation Expectations

- Unit tests for containment, traversal, symlink/resolution behavior as feasible, and denied path categories.
- Forbidden-write fixture tests used by create workflow.
- Negative acceptance test proving no ad hoc string-only path validation is used where the guard should be called.

## Non-Lens Negative Acceptance Criteria

- Do not write or require `feature.yaml`, governance publish, direct governance repo writes, governance docs mirror writes, Lens branch topology, Lens constitution runtime, release clones, `.github`, Lens control-repo implementation paths, current NextLens top-down runtime modules, Landscape, Derived Graph, Salmon, promotion, adjacency, pressure, roadmap, or service/domain/program truth paths.
