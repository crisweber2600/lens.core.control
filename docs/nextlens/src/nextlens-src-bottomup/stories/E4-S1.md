# Story E4-S1: Write Standalone Module README and Command Documentation

Status: done

## Story

As an operator, I want documentation that explains Bottom-Up LENS plainly, so that I understand this is a standalone BMad module and not Lens governance.

## Implementation Context

- Dev implementation target: `NextLens` at `TargetProjects/nextlens/src/NextLens`.
- Implementation writes are allowed only under `TargetProjects/nextlens/src/NextLens`.
- Documentation must not instruct users to write Lens governance, release clones, control-repo implementation surfaces, current NextLens top-down runtime, Landscape, Derived Graph, Salmon, promotion, adjacency, or pressure outputs.
- Preserve the phrase "Start from one feature" before explaining Bottom-Up LENS terminology.

## Acceptance Criteria

1. Given README and command docs are reviewed, when users read them, then they explain "Start from one feature", setup, create, validate, verify, output paths, packet validity, BMAD readiness, and non-effects receipts.
2. Given docs mention Bottom-Up LENS, when they are read, then they preserve the phrase "Start from one feature" and explain Bottom-Up LENS after the plain-language concept.
3. Given docs mention Lens-origin concepts, when they are reviewed, then they clarify that the module does not publish governance, create Lens branches, enforce Lens constitution runtime, write release clones, or depend on current NextLens top-down runtime modules.
4. Given Markdown is rendered, when screen-reader/plain-text checks are considered, then headings, status labels, examples, and paths remain understandable without color.
