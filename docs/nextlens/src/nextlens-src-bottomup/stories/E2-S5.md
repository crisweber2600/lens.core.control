# Story E2-S5: Implement Receipt and Run-Metadata Verification

Status: done

## Story

As a support user, I want receipt claims verified against run metadata and changed files, so that false non-effects claims are hard failures.

## Implementation Context

- Dev implementation target: `NextLens` at `TargetProjects/nextlens/src/NextLens`.
- Implementation writes are allowed only under `TargetProjects/nextlens/src/NextLens`.
- Runtime verification is read-only unless optional reports write under configured `reports_output_path`.
- This verifier must exist before packet creation can claim accepted-packet success.

## Acceptance Criteria

1. Given `bul-verify-receipt` receives a receipt and run metadata, when verification runs, then it compares `writtenFiles`, `changedFiles`, and `nonEffects` claims against forbidden path categories.
2. Given a valid receipt and matching run metadata, when verification runs, then it returns `status=pass` and `Non-effects verified` with checked-file summary.
3. Given a false-receipt fixture claims no graph update but changed files include a graph path, when verification runs, then it returns `status=fail`, labels the run invalid, reports `Receipt mismatch detected`, and includes violated category plus changed-file evidence.
4. Given required metadata is missing, when verification runs, then it fails closed and writes no accepted verification result outside optional report scope.
5. Given create workflow integration is attempted, when this verifier is absent or failing, then the create workflow cannot claim accepted-packet success.

## Tasks / Subtasks

- [ ] Verify receipt claims against run metadata, `writtenFiles`, and `changedFiles`.

- [ ] Add optional report behavior guarded by `reports_output_path`.
