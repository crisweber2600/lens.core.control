# Story E4-S4: Finalize Read-Only State Contracts and Package Validation

Status: ready-for-dev

## Story

As a maintainer, I want final release validation to preserve read-only future handoff and reporting contracts, so that downstream consumers can read packet state without mutation.

## Implementation Context

- Dev implementation target: `NextLens` at `TargetProjects/nextlens/src/NextLens`.
- Implementation writes are allowed only under `TargetProjects/nextlens/src/NextLens`.
- Package validation and read-only consumers must not write `feature.yaml`, governance repos/mirrors, release clones, Lens branch topology, Lens constitution runtime, current NextLens top-down runtime modules, Landscape, Derived Graph, Salmon, promotion, adjacency, pressure, roadmap, or service/domain/program truth paths.
- This story closes release readiness only after metadata, docs, examples, fixtures, tests, and evals pass.

## Acceptance Criteria

1. Given package validation runs, when the module is ready for distribution, then module validation, unit tests, fixture tests, and evals pass before release.
2. Given future reporting or BMAD handoff reads packet state, when it consumes status, provenance, packet validity, and BMAD readiness fields, then it can do so without mutating packet state or promoting topology.
3. Given constitutional traceability is reviewed, when full-track artifacts are mapped, then PRD/UX/product/research/brainstorm are treated as the business-plan equivalent and `architecture.md` is treated as the tech-plan equivalent.
4. Given FinalizePlan readiness is assessed, when this story is complete, then the story bundle is ready for story-file generation, but dev readiness is not claimed until required story files with frontmatter are produced.

## Tasks / Subtasks

- [ ] Run or document the full module validation command/release checklist.
- [ ] Confirm package metadata, docs, fixtures, unit tests, evals, and module validation readiness.
- [ ] Preserve read-only packet state fields for future reporting and BMAD handoff consumers.
- [ ] Record full-track artifact equivalence for constitutional planning requirements.

## Dependencies And Sequencing

- Depends on: E1-S4, E4-S1, E4-S2, E4-S3.
- This is the final release-readiness story and should not bypass any prerequisite story checks.
- Completion means the module is package-validation ready, not that Lens governance or topology promotion is implemented.

## Dev Notes

- Read-only consumers may read status, provenance, packet validity, and BMAD readiness; they must not mutate packet state or promote topology.
- Keep full-track constitutional traceability explicit: product brief, research, brainstorm, PRD, and UX together satisfy business-plan equivalence; architecture satisfies tech-plan equivalence.
- Future promotion, adjacency, pressure, Salmon, Landscape, and Graph workflows remain out of MVP scope.

## Test / Validation Expectations

- Full validation command or release checklist passes.
- Read-only consumer contract tests for status/provenance/validity/readiness fields.
- Traceability check for business-plan and tech-plan artifact equivalence.

## Non-Lens Negative Acceptance Criteria
