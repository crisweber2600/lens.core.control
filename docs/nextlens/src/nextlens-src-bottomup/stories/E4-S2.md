# Story E4-S2: Maintain Golden Valid and Invalid Examples

Status: ready-for-dev

## Story

As a maintainer, I want examples and fixtures synchronized with validators, so that docs and tests prove the same contract.

## Implementation Context

- Dev implementation target: `NextLens` at `TargetProjects/nextlens/src/NextLens`.
- Implementation writes are allowed only under `TargetProjects/nextlens/src/NextLens`.
- Fixtures and examples must remain read-only inputs during validation/eval execution except generated reports under configured `reports_output_path`.
- Examples must preserve archive evidence as distinct from Living Landscape truth and Derived Graph projection.

## Acceptance Criteria

1. Given examples are inspected, when maintainers review fixtures, then they include valid packet, invalid multi-candidate, invalid missing explicit out-of-scope, forbidden write, false receipt, and valid-not-BMAD-ready cases.
2. Given validator rules change, when fixture tests run, then outdated examples fail until they are updated to match the handwritten Python validation contract.
3. Given examples are read by users, when they compare valid and invalid cases, then they can see why packet validity differs from BMAD readiness.
4. Given examples include topology fields, when they are inspected, then topology remains null/unpromoted and no Landscape/Graph truth is implied.

## Tasks / Subtasks

- [ ] Add valid and invalid packet examples.
- [ ] Add false receipt and forbidden changed-file examples.
- [ ] Add valid-not-BMAD-ready example.
- [ ] Keep examples synchronized with validator, readiness, and verifier output keys.

## Dependencies And Sequencing

- Depends on: E2-S2, E2-S3, E2-S5, E3-S4.
- This story should reuse the actual validator/readiness/verifier contracts rather than invent parallel example shapes.
- E4-S3 depends on these examples for artifact eval fixtures.

## Dev Notes

- Fixture names should align with architecture guidance such as `valid-*.json`, `invalid-*.json`, `receipt-*.json`, and `false-graph-receipt.json`.
- Topology fields must stay null/unpromoted in examples.
- Examples should show packet validity and BMAD readiness as separate outcomes.

## Test / Validation Expectations

- Golden fixture tests for every listed case.
- Example-doc synchronization check against validator output keys.
- Artifact eval fixtures reuse these examples.
