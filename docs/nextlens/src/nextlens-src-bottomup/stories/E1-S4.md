# Story E1-S4: Complete Marketplace and Package Metadata Decisions

Status: done

## Story

As a distributor, I want package metadata decisions captured in the module, so that the installable module can pass validation without cleanup drift.

## Implementation Context

- Dev implementation target: `NextLens` at `TargetProjects/nextlens/src/NextLens`.
- Implementation writes are allowed only under `TargetProjects/nextlens/src/NextLens`.
- This story completes package metadata decisions for the standalone BMad module and must not imply Lens governance installation.

## Acceptance Criteria

1. Given package metadata is finalized, when `.claude-plugin/marketplace.json` and related docs are reviewed, then owner, repository, homepage, license, keywords, module name `Bottom-Up LENS`, module code `bul`, and version are explicit.
2. Given packaging validation runs, when metadata is incomplete, then validation fails with actionable guidance before release.
3. Given package metadata is authored, when boundary checks run, then it does not advertise Lens governance installation, Lens branch topology, or NextLens top-down runtime coupling.
4. Given dependency checks scan package metadata, when they run, then no current NextLens top-down runtime module is required.

## Tasks / Subtasks

- [ ] Complete `.claude-plugin/marketplace.json` required fields.
- [ ] Record owner, repository, homepage, license, keywords, module name `Bottom-Up LENS`, module code `bul`, and initial version.
- [ ] Add validation guidance for missing metadata.
- [ ] Ensure distribution copy presents Bottom-Up LENS as standalone packet creation and verification.
